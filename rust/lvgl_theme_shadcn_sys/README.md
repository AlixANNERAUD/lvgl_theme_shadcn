# lvgl_theme_shadcn_sys

Raw `no_std` FFI bindings to [`lvgl_theme_shadcn`](https://github.com/AlixANNERAUD/lvgl_theme_shadcn), a
shadcn/ui-inspired theme for LVGL 9.6+. Most users want the safe
[`lvgl_theme_shadcn`](https://crates.io/crates/lvgl_theme_shadcn) crate instead.

The build script compiles the theme's C sources with [`cc`](https://crates.io/crates/cc). LVGL itself is not built
or linked here: it is provided by whatever crate or build system already supplies LVGL to your application.

The bindings cover the whole C API, including `lv_theme_shadcn_set_radius`, `lv_theme_shadcn_set_size`,
`lv_theme_shadcn_set_text_role` and `lv_theme_shadcn_set_role`, and the `lv_theme_shadcn_fonts_t` struct with its
heading fonts `h1`, `h2` and `h3`. Build the fonts struct with every field set, since Rust has no partial initialisers.

## Locating LVGL

The build script looks for LVGL headers and `lv_conf.h` in this order:

1. `DEP_LVGL_INCLUDE` and `DEP_LVGL_CONF_PATH`, exported by a dependency declaring `links = "lvgl"`.
2. `LVGL_INCLUDE_DIR` and `LV_CONF_PATH` environment variables.

`LVGL_INCLUDE_DIR` is the LVGL root directory (the one containing `lvgl.h`); `LV_CONF_PATH` is the directory
containing `lv_conf.h` (a path to the `lv_conf.h` file itself is also accepted), which is included with `LV_CONF_INCLUDE_SIMPLE`. Use the same `lv_conf.h` as the LVGL build
you link against. The build fails with an explanatory message if neither pair is set.

When `DOCS_RS` is set, C compilation is skipped so documentation builds without LVGL.

## Linking a prebuilt LVGL

If `LVGL_LIB_DIR` is set, the build script also links `liblvgl.a` from that directory
(`cargo:rustc-link-lib=static=lvgl`). This is meant for tests and CI, where LVGL is built separately with CMake:

```sh
cmake -S rust/ci -B build-rust-ci
cmake --build build-rust-ci
export LVGL_INCLUDE_DIR=$PWD/build-rust-ci/_deps/lvgl-src
export LV_CONF_PATH=$PWD/rust/ci/conf
export LVGL_LIB_DIR=$PWD/build-rust-ci/lib
cargo test -p lvgl_theme_shadcn_sys
```

## Bindings

`rust/lvgl_theme_shadcn_sys/src/bindings.rs` is generated by `generate-bindings.sh` (requires `bindgen-cli` and libclang) and committed, so
no libclang is needed by default. Every LVGL type except `lv_color_t` is opaque, so the bindings do not depend on
`lv_conf.h`. The `bindgen` feature regenerates the bindings at build time instead.

## Notes

- C enums cross the FFI boundary as `c_uint`. Targets whose C compiler uses `-fshort-enums` must build the C side with
  the same ABI; `cc` honours the `CFLAGS` environment variable (for example `CFLAGS=-fshort-enums`).
